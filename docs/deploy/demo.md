# Wave Team Pro demo deployment

A separate, white-labelled copy of the platform for sales demos. It has its own Supabase project
(e.g. `wave-team-pro-demo`) and Vercel project, and contains only the fictional **Solenne Systems Group**
(five companies: London, Amsterdam, Singapore, Miami, Bangkok; 23 people; @solenne.example).

## Database (demo project only)
1. Structure: every file in `supabase/migrations/`, in order.
2. `supabase/demo/01_engine.sql`: the `demo` schema and `demo.refresh()`.
3. `supabase/demo/02_seed.sql`: the demo company (generated by `python3 scripts/demo/build_seed.py`).
   It refuses to run if the database already has companies.
4. `supabase/demo/03_schedule.sql`: pg_cron runs `demo.refresh()` hourly.

`demo.refresh()` keeps the demo current: clock-ins appear as each office's day goes by, finished
weeks' timesheets are submitted then approved, next week's shifts are planned, and the fixed story
(tasks, leave, expenses, chat, communications, project dates) moves forward with the calendar.

## Vercel (demo project)
| Variable | Value |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | demo project |
| `SUPABASE_SERVICE_ROLE_KEY` | demo project (Sensitive) |
| `APP_BASE_URL` | the demo site URL |
| `RATE_LIMIT_SALT`, `CRON_SECRET` | random |
| `NEXT_PUBLIC_PRODUCT_NAME` | `Wave Team Pro` |
| `NEXT_PUBLIC_HUB_NAME` | `Group Hub` |
| `NEXT_PUBLIC_GROUP_NAME` | `Solenne` |
| `NEXT_PUBLIC_EXAMPLE_DOMAIN` | `solenne.example` |
| `NEXT_PUBLIC_EXAMPLE_COMPANY` | `Solenne Systems` |
| `NEXT_PUBLIC_DEMO_MODE` | `1` (one-click demo sign-in, banner, account security locked) |
| `DEMO_PASSWORD` | the demo password |

No Microsoft 365 or email keys: the demo never sends email or calendar invites.
